修复：每分钟的例行检查会把还在跑的那一轮判成「上下文被销毁」，清掉它的运行锁和缓存，然后因为补跑额度已满而直接等下一个执行点。

- 判死（探活 + 清锁清缓存）从「每次敲门」挪到「确实要开跑的那一刻」，空敲门只做最便宜的粗筛
- 探活结论再用时间戳复核：1 分钟内还有活动就按「仍在跑」处理，不再误杀被 Chrome 冻结的轮次
- 浏览器重启 / 脚本重新启用 / 睡了很久这类换会话场景，不再额外补跑一次，避免白烧额度
- 探活耗时后重算当前时刻与执行点，避免漏掉刚过点的那一班

日志变化：非执行点不再出现「♻️ 新会话（上一轮跑到一半上下文被销毁）」和「补跑已用满 X 次」；真被打断时是「♻️ …（已安静 N 分钟）」紧跟「🩹 当场补跑（今日第 1/4 次）」。
