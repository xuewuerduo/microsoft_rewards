修一个把整晚排程带偏的解析 bug：收工时刻顺延到「次日 00:00」时，计划被判成「区间太窄」整份丢弃，脚本于是沿用上一次会话的旧开机时刻，连 hold 闸门一起失效。

- 收工分钟 ≤ 开机分钟 = 跨天，按「今天 23:59 收工」处理，执行点正常撒点（此前只要跨天就必丢）
- 计划新鲜度加一条：写入时刻早于本次浏览器启动 5 分钟以上，判为上一轮残留，丢弃
- 读不到计划时日志带原因（端口/超时/内容/旧计划），10 分钟节流，不再每分钟刷一条
- 缓存复用不再依赖 performance.timeOrigin（脚本猫每次敲门都是新上下文，该值每次都变），改为每 3 分钟允许复核一次开机时刻，记录落盘
- hold 查询节流改落盘 30 秒，跨上下文有效
- 扩展校准不再抛 AttributeError: 'bool' object has no attribute 'get'
- zy.py 计划自检比对内容里的 startAt，端口上若是上一轮残留实例应答会当场告警

日志变化：读到计划会写「收工 23:59（次日 00:00，按今日 23:59 收工）」；开跑前若校准还没结束，会出现「⏸️ zy.py 正在安装/校准脚本猫」，且开跑时刻一定晚于「🔓 已放行」。
