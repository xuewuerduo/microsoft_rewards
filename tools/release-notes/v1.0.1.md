## v1.0.1 · 运行时段交给 zy.py 定，脚本不再和面板各算一套钟

只改了一处闸门，任务逻辑没动。

### 修的问题

容器里 `zy.py` 决定「几点开机、几点收工」，脚本自己又按面板 `运行时段`（默认 09:00~23:00）判一次。
两边一旦错位，脚本会**安静地不干活**：到点以后每次唤醒只打一行
`🌙 当前不在运行时段（09:00~23:00…），本次唤醒不跑任务` 就返回，`zy.py` 却还在等它跑完。
典型场景是面板起晚、手动重启、某天顺延到深夜 —— 那天就是全程空转、0 产出。

### 现在的做法

- `zy.py` 把本轮**实际收工时刻**写进端口表（`/zy-ports.json` 的 `runUntil` 字段，epoch 毫秒）。
- 脚本认领端口时顺手记下它：只要还没到那个时刻，就视为**在运行时段内**。
- 读不到（脱离容器单独用、或用旧版 zy.py）→ 完全按面板 `运行时段` 走，**行为和以前一模一样**。
- 收工时刻过后自动失效，不会因为残留值整夜跑。

### 另外

- `zy.py` 里那两条互相打架的提示（「收工顺延到 23:59」紧跟「按 23:59 准点收工，不做顺延」）已合并成一条，
  并新增「实际可用不足一轮硬上限 40 分钟」的预警。
- 这个版本需要配套的 `zy.py`（4780 行 / `a93cef35`）一起上传才生效；只升脚本不会变坏，只是仍按面板时段走。

### 看日志验证

出窗后开跑时会出现：

```
🕘 运行时段由 zy.py 接管：收工 23:59（面板 winTime 本次不生效，容器里作息以 zy.py 为准）
```

正常在窗内（白天）不会出现这行，属正常现象。
